# 0001. 기존 에이전트 도구를 MCP 서버 하나로 묶기

- 상태: 채택 (2026-10-30, 사용자 합의)

## 맥락

- stat/corp/air/realty-agent는 각자 웹 화면 안에서만 Claude tool-use로 동작한다.
  FDE 업무의 핵심은 "고객이 이미 쓰는 도구 안으로 들어가는 연동"인데, 지금 도구들은 내 웹사이트 밖에서 쓸 수 없다.
- MCP 서버로 만들면 Claude Desktop/Code나 사내 에이전트에 설정 한 줄로 꽂을 수 있다.
  서버 자체는 LLM을 부르지 않으므로 Claude 비용은 0, 공공 API 호출 한도만 쓴다.

## 결정

1. **새 레포에 복사(vendoring)**. 4개 레포를 패키지로 만들어 의존하는 방법도 있지만,
   air/realty가 비공개 레포라 다른 사람이 설치할 수 없고 4개 레포를 다 고쳐야 한다.
   원본 커밋과 바꾼 점은 `VENDORED.md`에 기록한다.
2. **원래 스키마·설명문을 그대로 노출**. 정답셋으로 다듬어진 문구라 새로 쓰지 않는다.
   그래서 함수 시그니처에서 스키마를 만드는 `MCPServer` 대신 저수준 `Server`를 쓰고,
   인자 검증은 원래 스키마로 `jsonschema`가 한다.
3. **도구 이름에 도메인 접두어** (`kosis_get_data`, `realty_today` …). 여러 MCP 서버가 같이 꽂히면
   `get_data`, `today` 같은 이름이 겹치거나 모델이 헷갈린다. 설명문 속 같은 도메인 도구 이름도 같이 바꾼다.
   테스트가 "접두어 말고는 원본과 같다"를 확인한다.
4. **키가 있는 도메인만 노출**. 못 쓰는 도구를 보여주면 모델이 호출했다 실패하는 왕복만 는다.
   꺼진 도메인과 키 발급처는 stderr에 남긴다.
5. **모든 도구에 `read_only_hint`**. 조회만 하고 아무것도 바꾸지 않는다.
6. **1차는 로컬(stdio)**. 사용자가 자기 키로 설치. 2차로 원격(Streamable HTTP) 서버를 검토한다
   (내 키 한도·남용 방지·Render 잠듦 문제를 그때 결정).

## 기각한 대안

- 레포마다 MCP 서버 4개: 사용자가 4번 설치·설정해야 하고 "하나로 묶는다"는 목적과 멀어진다.
- `MCPServer` + 함수 시그니처로 스키마 자동 생성: 16개 도구의 파라미터 설명을 다시 써야 하고 원문과 달라질 위험.
